H.E.
Harness Engineering

Grow a chat into a harness.

Work with an AI agent starts as a chat. When it turns out to have a purpose and to repeat, the prompt does not survive the next session — or the next agent. A harness does: documents, a procedure and a hash chain that keep what was wanted, what was done and what remains.

View on GitHub 5-minute quick start

Why

  • An agent forgets everything when the conversation ends. The next session can only pick up what is left in files.
  • So the core of a harness is not the prompt but the record: what was wanted → how it was planned → what was executed → how the code changed → what remains.
  • That record must be trustworthy, so it behaves like a ledger: append-only, tamper-evident, reproducible from the first document.

How it works

This repository is a seed. Clone it into a project folder and ask your agent to run build_skill.md. It harvests the conversation, confirms the purpose and rules with you, and plants:

docs/

The backbone. Six documents per work item, linked by hashes.

SKILL.md

The procedure: what to write into docs/, and in what order.

chain.py

A small tool that proves docs/ is connected and unchanged.

One work item, six documents

REQ→PLAN→INS→TASK (code)→LOG→HISTORY→ next REQ
DocumentAnswers
REQWhat is wanted? Requirements with acceptance criteria
PLANHow will it be done? Each item answers a requirement
INSWhat exactly is executed?
TASKWhat code remains? A manifest that hashes the whole code folder
LOGHow did the code's concept and logic change? — the timeline of the code
HISTORYWhat was achieved, what remains? — the timeline of the work, feeding the next REQ

Code lives in two places: scripts/ for what you work with (tests, drafts, tools), and vendor/{app}/ for what gets deployed — only after it has been verified in scripts/.

Like a blockchain

PropertyHow the harness keeps it
DeterminismA hash depends only on content — not on time, person or location
DeduplicationThe work sequence is the nonce; a duplicate is refused; sealing twice changes nothing
IntegrityTampering, deletion, stray files and ledger edits are all detected
Consistencyverify replays from the first document and prints one head hash — same docs, same head, for everyone
FinalitySealing is final; a mistake is corrected by a new work item, never by editing

These are tested, not just stated: tests/property_test.sh tries to break each property and checks that the tool refuses or reports it.

Quick start

In your project folder:

git clone https://github.com/walktothemoone-creator/harness_engineering_apk.git harness_engineering

Then, in the same chat where the context is, tell your agent:

Read harness_engineering/build_skill.md and build a harness
in this folder from what we have discussed so far.

Or try the tools by hand:

python3 harness_engineering/tools/seed.py init --prefix DEMO --title "Demo workspace"
python3 scripts/_shared/chain.py new first_task "DEMO first task"
python3 scripts/_shared/chain.py seal --dry-run

Requires Python 3.8+ (standard library only) and git. Built with Claude Code, but any agent that reads Markdown and runs commands can follow it. Korean: add --lang ko.

Privacy policy

채팅을 하네스로 키운다.

AI 에이전트와 하는 일은 채팅으로 시작합니다. 그 일에 목적이 있고 반복된다는 걸 알게 되면, 프롬프트는 다음 세션이나 다음 에이전트까지 살아남지 못합니다. 하네스는 살아남습니다. 무엇을 원했고, 무엇을 했고, 무엇이 남았는지를 문서와 절차, 해시 체인으로 남깁니다.

GitHub에서 보기 5분 빠른 시작

왜

  • 에이전트는 대화가 끝나면 모든 것을 잊습니다. 다음 세션이 이어받을 수 있는 것은 파일로 남은 것뿐입니다.
  • 그래서 하네스의 핵심은 프롬프트가 아니라 기록입니다. 무엇을 원했고 → 어떻게 하기로 했고 → 무엇을 실행했고 → 코드가 어떻게 바뀌었고 → 무엇이 남았는가.
  • 그 기록은 믿을 수 있어야 하므로 원장처럼 다룹니다. 덧붙이기만 하고, 고치면 드러나고, 첫 문서부터 다시 계산해도 같은 결과가 나옵니다.

어떻게 동작하나

이 저장소는 씨앗입니다. 프로젝트 폴더에 clone 하고 에이전트에게 build_skill.ko.md를 실행시키면, 대화를 수확해 목적과 규칙을 확인받은 뒤 다음을 심습니다.

docs/

뼈대. 작업마다 문서 여섯 개가 해시로 이어집니다.

SKILL.md

절차. docs/에 무엇을 어떤 순서로 쓰는지 정합니다.

chain.py

docs/가 이어져 있고 바뀌지 않았음을 확인하는 작은 도구.

작업 하나, 문서 여섯 개

REQ→PLAN→INS→TASK (코드)→LOG→HISTORY→ 다음 REQ
문서답하는 질문
REQ무엇을 원하는가? 완료 기준이 있는 요구사항
PLAN어떻게 할 것인가? 항목마다 대응하는 요구사항
INS구체적으로 무엇을 실행하는가?
TASK어떤 코드가 남았는가? 코드 폴더 전체를 해시로 묶은 목록
LOG코드의 개념과 로직이 어떻게 바뀌었는가? — 코드의 시간축
HISTORY무엇이 됐고 무엇이 남았는가? — 일의 시간축, 다음 REQ로 이어짐

코드는 두 곳에 둡니다. scripts/는 내가 작업하는 코드(시험, 초안, 도구)이고, vendor/{앱}/는 배포되는 코드입니다. scripts/에서 검증한 것만 vendor/에 적용합니다.

블록체인처럼

성질하네스가 지키는 방식
결정론적 실행해시는 내용만으로 정해집니다. 시각, 사람, 위치와 무관합니다
중복 실행 방지작업 순번이 논스입니다. 중복은 거부되고, 두 번 봉인해도 바뀌는 것이 없습니다
데이터 무결성변조, 삭제, 체인 밖 파일, 원장 수정이 모두 드러납니다
상태 일치성verify가 첫 문서부터 다시 계산해 head 해시 하나를 냅니다. 같은 docs면 누구에게나 같은 head
완결성봉인은 확정입니다. 틀린 것은 고치지 않고 새 작업으로 바로잡습니다

말로만 정한 규칙이 아닙니다. tests/property_test.sh가 각 성질을 깨 보고, 도구가 거부하거나 알려 주는지 확인합니다.

빠른 시작

프로젝트 폴더에서:

git clone https://github.com/walktothemoone-creator/harness_engineering_apk.git harness_engineering

그리고 대화 맥락이 남아 있는 같은 채팅에서 에이전트에게:

지금까지 나눈 내용으로 이 폴더에 하네스를 만들어 줘

python3 scripts/_shared/chain.py new first_task "DEMO 첫 작업"
